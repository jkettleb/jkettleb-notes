Operational suite
^^^^^^^^^^^^^^^^^

The expected state at the end of the hindcast go live is in the following table.  In the table 'fc' means both seasonal and short forecasts.

=============   =====  =====  ====  ===========
Configuration   fc/hc  os/ps  cylc  id
=============   =====  =====  ====  ===========
GC3.2           fc     os     7     os46-bridge
GC5.1           hc     os     8     os47
GC5.1           fc     ps     8     os47-bridge
=============   =====  =====  ====  ===========

Note: 'bridging suites' may, in practice, have a more descriptive name.

Expect to get to this state from standard ps running:

   1. Turn off hindcasts in GC3.2 OS46 suite (rose-suite.conf edit)
   2. Turn off forecasts in GC5.1 PS47 suite (rose-suite.conf edit), update hindcast control file (rose-app.conf edit) and make live (sym links)
   3. Start up a GC3.2 forecast only suite (bridging)
      
      * uses the JULES dump from GC5.1 PS47 location  

Proposed route for implementation is to:
   1. create a JIRA issue for each of these workflows. These JIRA issues give the instructions (e.g. any file copies, working copy updates, etc) to set up each workflow.
   2. Operational suite team to use the JIRA to create the implementation plan
   3. GloSea team to review.
